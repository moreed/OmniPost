# Implementation Plan: Firebase Auth & Cloudflare R2 Integration

## 1. Overview & User Requirements
The OmniPost Studio cross-posting application requires:
1. **Firebase Authentication**:
   - Authentication method: **Admin Email & Password only** (per user clarification).
   - Session management, token persistence, and role-based access control.
   - Integration with Firebase SDK (`firebase/app`, `firebase/auth`, `firebase/firestore`).
   - Firestore security blueprint (`firebase-blueprint.json`) and hardened security rules (`firestore.rules`) enforcing admin permissions.
   - Seamless coexistence with the existing 2FA TOTP authenticator flow (Email/Password -> 2FA TOTP verification -> Admin Access).

2. **Cloudflare R2 Object Storage**:
   - Primary purpose: **High-speed hosting and CDN delivery for rendered 4K/60fps videos and high-res cover images** generated by Video Studio and Image Studio.
   - Configuration UI: **Secure in-app settings panel with connection verification** inside the Admin cPanel.
   - Key settings: Cloudflare Account ID, Access Key ID, Secret Access Key, R2 Bucket Name, and Public CDN Domain / R2 Dev URL.
   - Features:
     - Live connection handshake test (verifying bucket access, write permissions, and latency).
     - Direct "Upload to Cloudflare R2" action within Video Studio and Image Studio.
     - Automatic public media URL generation for multi-platform posting payloads (Facebook, TikTok, YouTube, Instagram).

## 3. Step-by-Step Implementation Strategy

### Phase 1: Firebase Auth & Firestore Foundation
1. **Firebase Configuration & SDK Setup**:
   - Create `src/services/firebase.ts` to initialize Firebase App, Auth (`getAuth`), and Firestore (`getFirestore`).
   - Graceful fallback: If Firebase is not yet provisioned in the environment, provide a local mock/demo mode so the app never crashes or becomes inaccessible.
   - Implement `handleFirestoreError` per skill guidelines with detailed JSON error diagnostics.
2. **Firebase Blueprint & Security Rules**:
   - Define `firebase-blueprint.json` specifying `admins` and `media_assets` collections.
   - Write hardened `firestore.rules` requiring email verification, role check, and blocking orphaned updates.
3. **Admin Login Integration (`AdminLoginModal.tsx` & `AdminCPanel.tsx`)**:
   - Update Step 1 of Admin Login Modal to accept Admin Email and Password, authenticating via Firebase `signInWithEmailAndPassword` (with fallback to default admin credentials).
   - Once authenticated via Firebase Auth, proceed to Step 2 (Authenticator App TOTP verification with live countdown and backup codes).
   - Display active Firebase Auth user email, UID, and token status in the Admin cPanel header.

### Phase 2: Cloudflare R2 Storage Engine & In-App Settings
1. **Cloudflare R2 Utility (`src/services/cloudflareR2.ts`)**:
   - S3-compatible client or signed REST API operations for Cloudflare R2 (`https://<account_id>.r2.cloudflarestorage.com/<bucket>`).
   - Secure storage of credentials in local encrypted settings (`localStorage` with masked keys in UI).
   - `testR2Connection()`: Uploads a test health probe object (`.probe.json`) and verifies read/write access and latency.
   - `uploadMediaToR2(fileBlob, fileName, mimeType)`: Handles chunked or direct upload of rendered canvas video blobs and high-res image canvases, returning public CDN URLs.
2. **Admin cPanel Cloudflare Tab**:
   - Add a dedicated **Cloudflare R2** tab in `AdminCPanel.tsx`.
   - Fields:
     - Cloudflare Account ID (32-character hex)
     - R2 Access Key ID
     - R2 Secret Access Key (with toggle show/hide)
     - R2 Bucket Name (e.g. `omnipost-media`)
     - Public CDN / Custom Domain (e.g. `https://media.omnipost.studio` or `https://pub-xxx.r2.dev`)
   - Interactive Handshake & Diagnostic Test:
     - Real-time connection ping testing credentials against Cloudflare R2 endpoint.
     - Displays status: Connected, Latency (ms), Bucket CORS status, Read/Write status.
   - Storage browser/metrics: Shows total uploaded assets, bucket size estimate, and quick link copy.

### Phase 3: Video Studio & Image Studio R2 Export Pipeline
1. **Video Studio (`src/components/VideoStudio.tsx`)**:
   - Add "Deploy to Cloudflare R2" button alongside existing MP4/WebM download and post attachment.
   - When clicked, renders canvas to blob, uploads directly to Cloudflare R2 bucket, and automatically assigns the public CDN video URL to the active social post.
2. **Image Studio (`src/components/ImageStudio.tsx`)**:
   - Add "Upload Cover to Cloudflare R2" button.
   - Automatically stores the generated 432Hz sacred geometry cover image on R2 and links it as the media attachment for social publishing.
3. **Platform Cross-Poster & Readiness**:
   - Update social posting cards to display Cloudflare CDN media badges when assets are hosted on R2.
